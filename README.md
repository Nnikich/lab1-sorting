# Лабораторная работа №1: Анализ и исследование алгоритмов сортировки

## Вариант №5

В рамках данной лабораторной работы исследуется эффективность различных алгоритмов сортировки при работе с массивами структур данных типа **«Преподаватель»** (`Teacher`).

---

## Описание предметной области и структуры данных

Объектом сортировки является структура `Teacher`, содержащая следующие поля:
1. **ФИО** (`fullName`) — строка вида `"Фамилия И.О."`
2. **Факультет** (`faculty`) — строка (например, `"ФИиВТ"`, `"ИЭиУ"`, `"ЕМФ"`, `"ГФ"`, `"ЮФ"`)
3. **Учёное звание** (`academicTitle`) — строка (напр., `"ассистент"`, `"старший преподаватель"`, `"доцент"`, `"профессор"`)
4. **Учёная степень** (`academicDegree`) — строка (напр., `"без степени"`, `"кандидат наук"`, `"доктор наук"`)

### Правила упорядочивания (Вариант 5)
Сравнение элементов структуры выполняется последовательно по следующим ключам (лексикографический порядок):
1. **Первичный ключ:** Факультет (`faculty`)
2. **Вторичный ключ:** ФИО (`fullName`)
3. **Третичный ключ:** Учёная степень (`academicDegree`)
4. **Четвертичный ключ:** Учёное звание (`academicTitle`)

Отношение строгого порядка реализовано в операторе `operator<` структуры `Teacher` с использованием `std::tie`:
```cpp
bool operator<(const Teacher& other) const {
    return std::tie(faculty, fullName, academicDegree, academicTitle) <
           std::tie(other.faculty, other.fullName, other.academicDegree, other.academicTitle);
}
```

## Реализованные алгоритмы сортировки

В проекте реализованы три собственных алгоритма сортировки, а также проведено сравнение со стандартным алгоритмом библиотеки C++:

1. **Пузырьковая сортировка (`Bubble Sort`)** — простая обменная сортировка с флагом оптимизации `swapped` (прекращение работы, если за проход не было обменов).
   - **Сложность:** $O(n^2)$ в среднем и худшем случае, $O(n)$ в лучшем (когда массив уже отсортирован).
   - **Память:** $O(1)$ (in-place).
   - **Стабильность:** Стабильный.
   - *Примечание:* из-за высокой вычислительной сложности замеры для пузырьковой сортировки ограничены размером массива $N \le 20\ 000$.

2. **Быстрая сортировка (`Quick Sort`)** — рекурсивная реализация Хоара с выбором опорного элемента (pivot) в центре диапазона.
   - **Сложность:** $O(n \log n)$ в среднем и лучшем случае, $O(n^2)$ в худшем (при крайне неудачном выборе опорного элемента).
   - **Память:** $O(\log n)$ вспомогательной памяти под стек вызовов.
   - **Стабильность:** Нестабильный.

3. **Сортировка слиянием (`Merge Sort`)** — классический алгоритм «разделяй и властвуй».
   - **Сложность:** $O(n \log n)$ во всех случаях (лучший, средний, худший).
   - **Память:** $O(n)$ вспомогательной памяти под временные буферы.
   - **Стабильность:** Стабильный.

4. **Стандартная сортировка (`std::sort`)** — гибридный высокооптимизированный алгоритм библиотеки C++ (Introsort), сочетающий быструю сортировку (Quick Sort), пирамидальную сортировку (Heap Sort) и сортировку вставками (Insertion Sort).
   - **Сложность:** $O(n \log n)$ гарантированно.
   - **Память:** $O(\log n)$ вспомогательной памяти.
   - **Стабильность:** Нестабильный.

## Инструкция по сборке и запуску

### 1. Компиляция и запуск бенчмарков (C++)
Для компиляции проекта используется система сборки CMake. Требуется компилятор с поддержкой стандарта C++17.

```bash
# Создание директории для сборки
mkdir build
cd build

# Конфигурирование и сборка
cmake ..
cmake --build .

# Запуск программы
./sort_test
```
При запуске программа проверит наличие исходных данных в директории `data/`. Если они отсутствуют, будет автоматически сгенерировано 12 CSV-файлов случайных объектов размером от 100 до 500 000 элементов. Результаты замеров запишутся в `results/times.csv`, а примеры отсортированных данных — в `results/sorted_*.csv`.

### 2. Визуализация результатов (Python)
Для построения графиков используется Python 3 со следующими зависимостями: `pandas`, `matplotlib`, `numpy`.

```bash
# Установка библиотек (если требуются)
pip install pandas matplotlib numpy

# Запуск скрипта построения графиков
python3 lab1/plot.py
```
После запуска скрипт сохранит 5 графиков в директорию `results/`:
- `graph_1_bubble.png` — Пузырьковая сортировка против теоретической сложности $O(n^2)$.
- `graph_2_quick.png` — Быстрая сортировка против теоретической сложности $O(n \log n)$.
- `graph_3_merge.png` — Сортировка слиянием против теоретической сложности $O(n \log n)$.
- `graph_4_stdsort.png` — `std::sort` против теоретической сложности $O(n \log n)$.
- `graph_all_comparison.png` — Совмещенный сравнительный график всех алгоритмов (в логарифмическом масштабе).

## Анализ полученных результатов

1. **Пузырьковая сортировка (`Bubble Sort`):**
   - Демонстрирует ярко выраженный квадратичный рост времени работы ($O(N^2)$).
   - Уже при $N = 20\ 000$ время сортировки составляет **45.62 секунды**, что делает алгоритм абсолютно неприменимым для обработки больших массивов.
   - Дальнейшие тесты для пузырьковой сортировки при $N \ge 50\ 000$ были прерваны по соображениям времени.

2. **Быстрая сортировка (`Quick Sort`) vs Сортировка слиянием (`Merge Sort`):**
   - Оба алгоритма показывают сложность, близкую к $O(N \log N)$, о чем свидетельствует график в логарифмических шкалах.
   - Быстрая сортировка стабильно обходит сортировку слиянием примерно на **7–10%** по скорости. Например, на максимальном размере $N = 500\ 000$ быстрая сортировка выполняется за **2.42 сек**, в то время как сортировка слиянием требует **2.61 сек**.
   - Такое преимущество Quick Sort объясняется меньшей константой в сложности (отсутствие дополнительных копирований векторов в куче и лучшая локальность данных при работе in-place).

3. **Сравнение с `std::sort`:**
   - Стандартный `std::sort` оказался абсолютным лидером по производительности.
   - На размере $N = 500\ 000$ он работает за **1.12 сек**, опережая самописную быструю сортировку более чем в **2 раза**!
   - Превосходство `std::sort` обусловлено глубокой оптимизацией компилятора, эффективным инлайнингом предикатов сравнения, отсутствием накладных расходов на рекурсию в простых случаях (переход на сортировку вставками для маленьких подмассивов) и защитой от худшего случая алгоритмом Introsort (переход на Heap Sort при превышении глубины рекурсии).

## Выводы

1. Экспериментально подтверждены теоретические оценки сложности алгоритмов:
   - Квадратичная для `Bubble Sort` — $O(N^2)$;
   - Линеаризованная для `Quick Sort`, `Merge Sort` и `std::sort` — $O(N \log N)$.
2. При разработке прикладного ПО для работы с большими массивами данных (от $10^4$ элементов и выше) необходимо использовать алгоритмы со сложностью не выше $O(N \log N)$.
3. Готовые высокооптимизированные стандартные функции (такие как `std::sort` в C++) предпочтительнее собственных простых реализаций быстрых алгоритмов, так как они учитывают аппаратные особенности работы кэша процессора и оптимизации компилятора.
